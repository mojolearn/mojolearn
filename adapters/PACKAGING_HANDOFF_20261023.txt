Scope and frozen source
-----------------------
Start from the latest origin/main containing the native MPS transport commit
991f6ade5. Freeze and record the full SHA before building. Preserve the older
adapters/qualification_20261023.json as historical AMD evidence, not a receipt
for changed artifacts. Read the newer MPS qualification record beside this file.

The optional Torch C++ operator and MAX custom operations both call the same
compiled Mojo adapter library. Numerical kernels are unchanged by this lane.
The new C ABI symbol mojolearn_adapter_operation_host_buffers accepts CPU
storage but REQUIRES GPU 0 and runs its arithmetic through DeviceExec. The
existing ABI and MAX package remain compatible (ABI 1).

Torch MPS transport is native ATen MPS-to-host copy, native Mojo upload,
identical GPU execution, native download, then native ATen host-to-MPS copy.
Copies preserve dtype and words; they are blocking and owners live until all
queues are drained. No reinterpretation of foreign Metal handles, Python
callbacks, CPU mathematical fallback, or new numerical implementation.
Keep all copies and synchronization inside any measured operation boundary.
There is no zero-copy or speed-improvement claim.

Actual Apple MPS execution remains REQUIRED and unqualified until run on an
authorized Apple test host. The requesting session prohibited local Apple
builds/tests: use an authorized remote Apple host, or obtain a changed owner
instruction in the receiving session. AMD forced-staging tests do not qualify
MPS, Metal interoperability, macOS linking, Apple Inductor or wheel installation.
Do not work around missing Mojo/Modular support; record the blocker and wait.

Deliverables
------------

   .mojoc extension with documented installation/activation. Reuse the existing
   platform/plugin packaging layout. Keep Torch and MAX optional: ordinary
   mojolearn installation/import must not load either framework or initialize
   its GPU. Preserve existing supported imports and model/estimator APIs.
2. Runtime initialization/registration is a native binding boundary; public
   numerical methods must remain one native call. No Python conversion,
   orchestration, callbacks, autograd fallback, or hidden computation.
3. Build each platform/target with the pinned Mojo/MAX versions and identical
   flags. Match LibTorch version, backend and C++ ABI to the tested framework.
   Pin supported Torch versions accurately; a single compiled extension is not
   automatically compatible with every Torch release/backend. Keep the compiler
   out of end-user installation and operation. Respect actual macOS deployment
   minimums, native dependencies, licensing and existing wheel audits.

   and retain required runtime libraries. Existing qualification build scripts
   use absolute test-environment search paths; those are not distributable wheel
   metadata. Exercise relocation from a clean venv after removing build paths.
5. Test installed wheels (not source-tree imports), merge packaging fixes into
   main, and retain ready-to-publish wheels plus manifests and full evidence.
   Follow the release owner's publication instructions. Do not publish public

Build and functional checks
---------------------------
Run on authorized machines; retain every exit code, complete log and artifact.
OUT is an absolute directory under /root/results-* on rented Linux hosts.
Use the equivalent retained directory on remote Apple hosts.

  bash tools/build_native_adapters.sh "$OUT" gfx942       # AMD
  bash tools/build_native_adapters.sh "$OUT" sm_89        # NVIDIA: use actual supported target
  bash tools/build_native_adapters.sh "$OUT" apple-native # real Apple GPU host; native GPU detection

Match the NVIDIA target to the actual GPU and accepted compiler evidence.
The Apple builder follows bindings/build.sh: no forced --target-accelerator
on the pinned compiler, since retained evidence shows that can omit Metal AIR.
Read embedded architectures/Metal payloads back and execute kernels before
admission; a successful compiler exit alone is insufficient.
The native builder saves command/source/compiler receipts and a 20-minute
process-group deadline. Never run unrelated GPU jobs alongside qualification.

  python tools/check_native_adapters.py --out "$OUT" --device cuda:0
  PYTORCH_ENABLE_MPS_FALLBACK=0 python tools/check_native_adapters.py --out "$OUT" --device mps
  python tools/check_native_adapter_abi.py "$OUT/libmojolearn_adapter.so" --json "$OUT/cpu-abi.json"
  python tools/check_native_adapter_faults.py --qualified-out "$OUT" --out "$FAULT_OUT" --device mps

On Apple, ensure both generic compile/export checks and the real MPS dispatcher
execute. A setup failure is not a successful rejection test. The test controller
records non-applicable CUDA stream coverage separately. No mandatory failure or
unsupported feature may silently turn into a passing/skipped case.

Required MPS cases: float32 arithmetic, int32 copies/indices/output, special FP32
word preservation, contiguous views with nonzero storage offsets, producer and
consumer ordering, no-input operation with mps and mps:0 device forms, output
shape/type refusals, mixed devices, noncontiguous tensors, repeated execution,
owner lifetimes, recovery after error, TorchScript/export and torch.compile.
Reject requires_grad until a separately implemented native backward is qualified.

Linux additionally exercises the same host-buffer GPU route without pretending

  mkdir -p "$STAGED_OUT"
  cp "$OUT/libmojolearn_adapter.so" "$STAGED_OUT/"
  python tools/check_native_adapters.py --out "$STAGED_OUT" --device cuda:0 --host-staging
  python tools/check_native_adapter_faults.py --qualified-out "$STAGED_OUT" --out "$STAGED_FAULT_OUT" --device cuda:0 --host-staging
  python tools/check_native_adapter_transport.py --library "$OUT/libmojolearn_adapter.so" --torch-library "$OUT/mojolearn_torch.so" --out "$TRANSPORT_OUT"
