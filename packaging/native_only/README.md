# Native-only smoke source inventory

This is an internal release-gate inventory, not a claim that all public Python APIs have interpreter-free equivalents. The runner is `tools/native_only_smoke.py`; the orchestrator compiles immutable source freezes. Lane agents do not compile.

Each ready case is a standalone Mojo executable with embedded inputs, checked consumed outputs, and a unique final marker. The runner's default execution budget is ten seconds per case, separately from compilation. GPU cases apply to Metal/CUDA/HIP; CPU cases use an actual host executor. Compilation and runtime acceptance must be recorded separately for each backend. A ready entry only means source is submitted.

`native-estimator` cases exercise a native fit/search/tokenizer operation and consumed output. `native-core` cases cover a narrower native engine or stage; each `coverage` field states what it does and does not cover. Neither scope certifies the corresponding Python-facing metadata, checkpoint, or distributed adapters. The optimizer fixture includes its own independent float64 formulas; the sequential fixture uses closed-form affine MSE and SGD predictions; the tape fixture checks the exact derivative of a branched polynomial. Existing estimator checks retain their original independent oracles and refusals. No case calls a Python binding or imports CPython.

The inventory is a static snapshot of explicit public export lists, expansion registries, selected namespace exports, and sklearn-compatible aliases. Alias rows intentionally remain visible. `not_algorithm` rows identify namespace/configuration/container exports and do not enter an algorithm denominator. `missing` rows have no reviewed bounded fixture. `blocked` rows name known public owners that depend on CPython ABI objects; adding a kernel fixture does not remove that blocker. Ready rows with a `boundary_blocker` have native engine coverage only. The public-name census can overinclude non-numerical helpers; their source path remains attached for review rather than silently dropping them.

The tokenizer uses the existing packaging-time Unicode table generator (`sh tokenizer/tools/gen_unicode_table.sh`). Its pinned Unicode table is compiled into the binary; neither corpus input nor interpreter access is needed at runtime. This build prerequisite is explicit in the manifest.

The initial source review resolved every local import closure with the existing native packager's conservative dependency walker, except the generated Unicode table before the stated prerequisite. This is static evidence only. Compiler failures, ten-second timeouts, missing native libraries, and untested vendors remain failures or pending cells in runner output. Running a binary with no Python shared library linked on the Mac is narrower evidence than running in the Linux interpreter-free root filesystem; the runner records these separately.

Alias accounting is explicit: every row has `canonical_algorithm` and `symbol_origin`; proven re-exports also have `alias_of`. These relationships come from static import/assignment/lazy-export resolution in `inventory.py`, never matching equal class names by spelling or importing the product. Each case lists its exact public names and a deduplicated `canonical_algorithms` list. The `census` separates alias rows, non-algorithm exports, and canonical numerical/helper entries. The latter still includes functions as well as estimators and must not be presented as a count of distinct estimators. Six controller tests retain the root/expansion census, exact fixture witnesses, alias evidence, boundary blockers, reproducibility, and operation scope.

Each case also states `whole_operation` and `operation_boundary`. The classifier/regressor neighbor cases call native search followed by prediction, but their reference vote/fold calculation reuses native search results and does not independently validate neighbor selection. The separate nearest-neighbor case supplies the search oracle. Native tape backward and multi-step optimizer fixtures cover their named engine operations; the separate public-owner blockers remain. Additional estimator fixtures cover scaler fit/transform/inverse, UMAP fit_transform, spectral clustering, HDBSCAN, single-linkage clustering, and ExtraTrees classifier/regressor fit plus GPU prediction. ExtraTrees uses exact analytic probabilities/targets and requires all three trained trees to split. These small datasets are smoke tests only, with no performance qualification or broader option-matrix claim.

The sequence optimizer cases cover Adagrad, Adamax, NAdam, centered momentum RMSprop and Lion through six native updates per configuration. They consume parameters, moment buffers, scalar state and unchanged gradients after every update, checking exact independent oracles and both branches of the Adamax/NAdam interpolation. `MOJOLEARN_NATIVE_OPTIMIZER_BAD_REFERENCE` deliberately changes one expected output word and must fail before a pass marker. Public optimizer adapters/checkpoints and the separate Adafactor/LAMB owners remain uncovered; source submission does not certify compilation or any GPU target.
