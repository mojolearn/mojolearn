# Two GPU suite runs, 2026-08-20 16:10-16:16 EDT: read before trusting a number from that window

## What ran

    16:10:40 - 16:12:40 EDT   full host suite, 13 tasks, launched by a subagent
    16:14:42 - 16:15:58 EDT   full host suite, 12 tasks, launched at merge

Both are GPU-heavy: `check-ctr-device`, `check-ctr-apply`, `check-model-io`
and `probe` all launch kernels.

## Why this file exists at all

This repository has already lost an hour to a concurrent GPU benchmark drifting
the box by roughly 4.5x, and the tell is that **the CPU canary stayed FLAT
while the GPU tanked** -- the contamination was invisible in the very arm that
would normally catch it. A stable CatBoost-CPU column does NOT certify a GPU
window. So a GPU window that overlapped other GPU work gets written down rather
than assumed clean.

## The actual risk here is LOW, and the reasoning is checkable

* No result file in `bench/results/` was written during either window. The most
  recent before them was `BOARD_2026-08-20_algorithm-matched.md` at 15:31:13,
  and the last benchmark-side file activity was `bench/bench_torch_mps.py` at
  15:54:02, which is authoring rather than measuring.
* Both runs went through `tools/with_build_lock.sh`, and the interleaved
  harness holds that same lock for the duration of a measurement (see
  `WINDOW_2026-08-20_interleaved-254.md`, "the build lock was held for the
  duration"). A measurement holding the lock would have BLOCKED these runs
  rather than overlapped them.

So this is a recorded window, not a known-bad one. **If a number was taken in
16:10-16:16 without holding the build lock, re-run it.** If it held the lock,
it is fine.

The first run happened because a subagent brief told it to run the full suite.
That instruction was wrong and has been retracted: **a lane runs only the
checks covering the code it changed, and the orchestrator runs the full suite
once, at merge.** The second run is that orchestrator run and is legitimate.
Written down because the reason a rule exists decays faster than the rule.
