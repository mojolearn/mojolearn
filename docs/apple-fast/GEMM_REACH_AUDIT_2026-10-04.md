## Integration order and actual coverage expansion

1. **First adapter subset:** one opt-in unfused FP32 dispatcher used by BOTH core NT/alias-Gram and `_fast_vendor_gemm` NN/NT. It imports only the low-level candidate, avoiding a core/identical-GEMM cycle. Preserve GEMV, unsupported TN, K0, input alias, capacities, caller buffer lifetimes and no-extra-sync contract. Per-route eligibility/counters must identify selected candidate and fallback. Keep default off, FAST+Apple only. G1/G5 quality is prerequisite, not proof of downstream quality.
2. **Expand unscored actual-dispatch matrix before timing:** exercise core NT, core alias-Gram, generic SDK NN and NT, plus explicit n1/K0/TN fallback checks. Include capped shapes representing tall GLM/PCA projection (4096x220 output, K220), low-width kmeans (4096x8,K220), distance blocks (257x259,K220), RBF projection NN (4096x256,K220), Gram (220x220,K4096), odd M/N/K, cancellation/dynamic range and true alias inputs. Poison outputs; compare independent FP64 errors to incumbent and G1/G5 words. Count routes rather than merely checking compile flags. This is matrix correctness coverage, not certification of estimator outputs.
3. **Before any board scoring/default:** compile affected real bindings and run unscored downstream quality with counters: core kmeans/knn labels/recall/distances; estimators OLS/ridge predictions and PCA components/reconstruction/KDE scores; kernel_methods RBF outputs/Nystroem/kernel-ridge predictions; SVM margins/predictions. Only families with nonzero reach and passing quality get a single A/B scored caller run. Do not issue 10-variant full-board sweeps. Preserve existing opponent measurements and all quality holds.
4. **Then shared AFN adapter:** extend common kernel policy to decomp/PCA while retaining their exact split boundaries/atomic policy; scoped compile switches per call family prevent hidden bundles. K16's narrow win/loss cannot justify changing long-K Gram accumulation.
5. **Separate fused adapters:** LU strided subtract, Cholesky lower-subtract and MCD active batched products may share tile-load/MMA code, but keep specialized address/epilogue/batch wrappers. First prove identity/no-regression and retention of fusion/one-launch batching. No generic materialization or precision downgrade to make interfaces uniform.

The useful simplification is shared tile/dispatch infrastructure with explicit operation policies, not one global performance knob. Early broad coverage should focus on the duplicated unfused SDK entrances; measured source-specific wins still require actual algorithm checks and call-plus-first-read timing.
