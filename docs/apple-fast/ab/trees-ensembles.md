# lane/apple-fast-trees-ensembles: the tools/bench_board_algos.py xlane="trees" ensemble lanes under FAST

Written without a Mojo toolchain (cloud peer); the first M3 build is the compile check
(bindings rf and x_trees: three new exports, no existing export changed). Every switch is an
env var read on the host at fit time, FAST tier only, default OFF; IDENTICAL (the default)
runs the old code. The models are the old FAST path's bits (same draws, same gathered bytes,
same fit entry; the native fold bookkeeping is index selection), so the AFC-AB digests must
match arm for arm.

| switch | kind | site | what it changes under FAST |
|---|---|---|---|
| `MOJOLEARN_TREES_ENSEMBLES_BAG_SESSION=1` | env (Python) | `python/mojolearn/_expansion_trees.py` `_BaggingBase._bag_session`, `_fit_bags`; `DecisionTreeClassifier._fit_rows_in_session`; `bindings/_mojolearn_rf.mojo` `rf_classifier_fit_session_rows_binding` (new export `rf_classifier_fit_session_rows_export`) | bagging-clf, bagging-reg: ONE device copy of X (a `ForestDataSession`) for the ten members; each member's bootstrap rows are gathered on the device (`launch_gather_rows_colmajor`) and fitted with `fit_forest` there (the regressor through the existing `rf_regressor_fit_session_rows_export`, the classifier through its new twin) |
| `MOJOLEARN_TREES_ENSEMBLES_NATIVE_SPLITS=1` | env (Python) | `_trees_native_folds`, `_trees_splits(native=)`, `OneVsRestClassifier._indicator`, `MultiOutputClassifier.fit`; `xtrees/ops.mojo` `stratified_folds`, `kfolds`, `fold_rows` (new exports `x_trees_stratified_folds`, `x_trees_kfolds`, `x_trees_fold_rows`) | stacking-clf, stacking-reg, calibrated: the cv=5 fold assignment and the ten fold row lists built natively instead of by Python loops over every row; ovr: the k one-vs-rest 0/1 targets through `x_trees_indicator_codes`; multioutput-clf: each label column of a float Y through `x_trees_column_f64` instead of `Y.tolist()` plus a per-column comprehension |

## Causes (the whole FAST fit path of each lane was read; `xtrees/ops.mojo` is a HOST binding: every glue op below runs on the CPU between the device fits)

- **bagging-clf / bagging-reg** (`_expansion_trees.py` `_fit_bags`, old loop): per member a host bootstrap draw (`sample_indices`, serial n draws), a host gather of n x d (`gather_f32`, host pool), then the member's own `fit` (`randomforest.py:460 _fit_arrays`): a ONE-thread `all_finite` over the gathered n x d, a transposition into the pinned stage and an upload (`_mojolearn_rf.mojo` `_rf_classifier_fit`, `_rf_regressor_fit`). At 1M rows that is ten gathers, ten finite scans and ten uploads per fit. Fixed behind BAG_SESSION (one upload, one finite scan, device gathers). Still host under the switch: the draws themselves (`x_trees_sample_indices`, serial) and the label gather (`gather_i32`, serial) -- a device RNG draw in one launch is owed (the rf binding's `FUSED_BOOTSTRAP_GATHER` kernels are the natural home; `ensemble/randomforest.mojo` is another family's).
- **adaboost-clf** (`_fit_members`, 50 rounds): per round `_w32` (host, n), the member's `_fit_weighted` on the SAME Xcm (staged per member unless `MOJOLEARN_FOREST_SESSION` is on), `est.predict(Xa)` which uploads the full row-major X AGAIN for the resident forest predict (`core/forest_inference.mojo` reads X row-major; the session holds it column-major, so a session-X predict needs a column-major predict kernel: owed, not done here), `x_trees_samme_step` (host, two serial passes over n, the weight update and its sum), a 4-value host readback and `x_trees_scale` (host, n). **adaboost-reg**: the same plus `x_trees_weighted_sample` (host pool) and the per-member row gather (device when the session is on, host otherwise) and `x_trees_r2_step` (host, serial). Only the session arm is queued; a device-resident weight plane updated by one launch per round is the next step (the glue binding has no device context today).
- **dart / dart-reg** (`_boost_loop`, 200 rounds): per round `x_trees_uniform` (host, 1 + t draws), the drop set on the host, `x_trees_gradients` (host, serial n), the member fit (X staged per member unless the session is on), `x_trees_apply` of the new tree over all n rows (host pool, DEVIATION 5608), `x_trees_leaf_newton` (host, serial n), `x_trees_tree_score_add` (host, serial n) and one more `tree_score_add` per dropped tree twice (remove, re-add rescaled). The score vector, g, h and the per-tree leaf ids live on the host for the whole fit. Only the session arm is queued; moving score/g/h resident with a (tree, row) apply launch and a per-leaf segmented reduction is a new device surface for `xtrees` (owed).
- **random-trees-embedding** (board median_ms = `fit(X)` only, `transform` is infer_ms): `fit` is `x_trees_uniform` (host, serial n draws for the random target), `as_f32_c` of it, then `ExtraTreesRegressor(max_features=1, max_depth=5, n_estimators=10).fit` (`extratrees.py:254 _fit_arrays`: ONE-thread `all_finite` over n x d -- 220M cells on Istella --, the row-major stage, the upload, then `extratrees/impl/decisiontree/batched_levelalgo/builder.mojo` ET_BINNED_REG: `compute_quantiles` and `et_bin_rows_kernel` over EVERY column, 220 on Istella, where the fit splits on at most 10 x 31 randomly drawn columns at depth 5; then five level cycles). The leaf gather + one-hot (`x_trees_apply` host pool, `x_trees_onehot_leaves` serial n x n_trees writing a dense n x n_output float64) is the untimed `transform`. Nothing changed here: the stage-times lines (`MOJOLEARN_STAGE_TIMES=1`, BOUNDARY_PYTHON binding_ms vs array_pack_ms, the builder's stage table) split fit between the Python stage, the binding and the builder; the IDENTICAL and FAST baselines size the tier gap. The likely fix (quantiles only for the drawn columns, or a sampled quantile pass) lives in the ET builder (other family) and `extratrees.py:278` (owned elsewhere).
- **stacking-clf / stacking-reg / calibrated** (`_fit_stack`, `CalibratedClassifierCV.fit`): `_trees_splits` built the folds with Python loops over every row (`_trees_stratified_folds`: a dict walk, a sort of n codes, k passes of n; `_trees_fold_rows`: two comprehensions of n per fold, so ten at cv=5) and `Array.from_list` of each list -- seconds at 1M rows; fixed behind NATIVE_SPLITS. Still host: `_gather` of each fold's X (host pool copy of 0.8 n x d per member per fold) and every sub-estimator (GaussianNB, DecisionTree, Lasso, LogisticRegression, Ridge) uploading its own fold X: a shared device X across sub-estimators needs those families' fit entries to take a resident X (owed to them).
- **ovr** (`fit`): the k 0/1 targets were list comprehensions over n (k = 4 taxi, 5 Istella) -- fixed behind NATIVE_SPLITS; each LogisticRegression clone then uploads X itself (owed to that family). **multioutput-clf**: `Y.tolist()` (n lists) and a per-column comprehension, then `encode_labels` of a Python list -- fixed behind NATIVE_SPLITS for a float Y (the board's). **multioutput-reg / voting-clf / voting-reg**: the wrapper's own work is one host accumulate per member at predict time; the fit is the sub-estimators' own fits on the shared Xa (each uploads it): nothing cheap at the wrapper level, no line queued.

## Keep rule

A switch becomes the FAST default when its arm is faster on the M3 and the AFC-AB digest matches the `-` arm (the change only reorders where X lives or who builds the index lists; the model bits must not move). `MOJOLEARN_FOREST_SESSION=share` may move bits (shared quantile table): keep only with held-out quality within FAST's run-to-run spread. The `te-*-ident` lines are the IDENTICAL baselines of every changed lane on Istella.
