# DBSCAN typed boundary and execution

DBSCAN fit, fit_predict and predict now unpack public metadata once and call the native DBSCAN descriptor. `core/dbscan_native_api.mojo` owns typed fit, core-count, core-gather, reference-prepare, direct-query and resident-query requests. The result word carries native integer counts/status/handles. The private core mask and direct-query chosen-index scratch are native lists. `core/dbscan_native_state.mojo` owns metric/method codes and resident identity, dimensions, handle and minting driver. RBC plus precomputed remains admitted, then takes the existing forced-brute route.

`bindings/dbscan_native_boundary.mojo` is the explicit Python storage/image/lifetime boundary. A stable opaque DBSCANHolder pins an immutable DBSCANReferenceOwner; actual handle, cache key and driver are Mojo state. A query pins its owner independently of a refit, public holder replacement or release. Resident reuse matches model/provider identity, buffer owner identities and addresses, dimensions and metric. The same existing freezable Arrays retain the resident route; rebound NumPy arrays retain direct queries so public mutations stay visible. The owner's destructor releases its minting provider's handle once; allocation failure cleans up the prepared handle. Both opaque types are registered once in `_mojolearn_runtime_family_host`.

The density lifecycle reuses KDE's existing native weak admission cache with a distinct DBSCAN slot and its own constructor schema. Cache stamps precede any GIL-released operation. It re-admits namespace keys and replaced owners after native teardown/run windows before publication. Pickle state strips the private holder and restores a fresh empty holder. The native owner-lifetime allowlist repair owned by the independent admission lane is a required companion dependency for replacement of estimators containing these owners; this batch does not weaken that lifetime policy.

The public fit still admits X once through its existing snapshot path; keeps the signed sample-weight route; runs the original fit; publishes iteration/label/dimension state in the original order; and performs the original distinct core-count and core-gather passes with the same destination sizes, device transfers and tuned kernels. It freezes/publishes the three core outputs and prepares residency in the same order. Empty-core prediction retains its early native parallel -1 fill before metric/eps consumption. Host budget refusal remains in the existing native host fit path. The old private `family_xc_dbscan_predict` entry now redirects through the same unpack/typed-query implementation with residency disabled, preserving its direct-upload route. Agglomerative helpers are unchanged.

Removed mechanisms: DBSCAN internal Python fit parameter lists, private core-mask Array, three-buffer result-list packing on the public path, unused chosen-index Python Array, Python resident holder dictionary/tuple/cache key, per-method Python callable dispatch, Python algorithm/arm/metric tables, duplicate legacy DBSCAN prediction envelope, and the density retained-binding list. Legacy exported low-level fit wrappers delegate to the same native providers; labeled-reference legacy entries remain for Agglomerative, and core-array legacy result packing remains for compatibility. No experiment, numerical kernel, tuned switch or supported public feature was removed.
