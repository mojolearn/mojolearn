# AgglomerativeClustering native migration

The additive API in `core/agglo_native_api.mojo` supplies named solver, general-tree and cosine-zero-row requests and direct fixed-span native drivers over the existing hierarchy solver/cluster and Xn descriptors. It retains both numerical fit owners: the single/Euclidean unconstrained/no-distance solver route and the existing general-tree route. It also supplies native two-word solver/scalar scratch and the existing per-row zero-flag storage. Shared labeled-reference request constructors deliberately supply fitted labels as both tie keys and output labels, metric zero, and no epsilon threshold; DBSCAN's different tie-key and threshold policies do not leak into this family.

`core/agglo_native_state.mojo` owns native metric/linkage/connectivity codes, fit options, full/partial-tree planning and reference-cache identity. The full-tree auto rule remains `max(100, 0.02 * n)`. Stored fitted owner identities remain the reference key; temporary admitted snapshot/view identities are not substituted. An active reference state retains its minting native driver and invalidates its handle exactly once on take. The native labeled-reference ABI/registry dependency is the completed DBSCAN batch, including its reviewed registry ownership repair.

The public switch now constructs typed options, bindings and requests. `AggloSettings` holds only the exact admitted public parameter owners until their established conversion/refusal points; it replaces the Python settings dictionary. Normalized metadata publication, scalar conversion order, solver/general-tree selection and both original output publication orders are retained. Public arrays retain zero-filled allocation, labels aliasing and the fitted-input snapshot policy. Native solver info, general-tree scalar results, cosine flags and chosen-reference scratch replace private Python arrays/envelopes. Exact scalar comparisons, hash admission and int/float conversion use native CPython entries; unsupported array diagnostics never enter NumPy formatters.

`AggloReferenceOwner` owns native handle/key/driver state and retains only provider/refs/labels Python pins. A stable `AggloHolder` pins that owner; active queries pin it independently through completion. Only the existing exact freezable Arrays become resident; mutable rebound NumPy buffers keep direct queries. Same-provider reuse follows stored fitted owner identities and dimensions, preserving the original cache policy. The two types are registered once by runtime_family_host and expose only their existing pins through the canonical native owner registry. Pickle state excludes residency; restoration admits replaced public owners, tears down old native state and restores a fresh holder. The registry consumer from the independent admission lane remains a required companion dependency.

Removed mechanisms: internal Python settings/fit argument dictionaries/tuples, Python info and cosine flag arrays, chosen-index Python Array, resident key/handle tuples/dictionaries, per-query Python numerical calls, family runtime linkage/metric/connectivity tables, both unused private residency modules and the redundant dynamic execution wrappers beside the hierarchy provider admission. The historical `family_xc_agglo_predict` operation remains as a direct native query without creating residency. The saved-model metric tables remain import-time schema metadata; no supported interface or tuned route was removed.

Remaining boundary staging is explicit: admitted public-value, storage and image pins; public argument/pickle schema; output publication; and sparse connectivity admission/conversion. Sparse CSR/CSC/BSR/COO/DIA/DOK/LIL conversion is unchanged in this batch and is assigned separately to the sparse-conversion lane. This batch does not move, parallelize or claim to complete that code. No numerical fit kernel, route/default switch, copy count or sparse algorithm was changed.

Native fixtures are owned by the test lane under `agglo_contract_*`, `agglo_state_*` and `agglo_native_*`. Original workload inventory includes the 18x2 grid, duplicate 36x2 data, 17-of-18 cluster cut and training/tie/near queries. The 200x4 seed-zero parallel controller remains a public multi-device seam. This lane runs no compilation, tests, timing, identity or box actions. All API/runtime evidence is owed to the orchestrator's combined batch; no performance or cross-device identity claim is made.

All 141 numerical/descriptor/connectivity sources compared to additive API commit `2121167e8471` are unchanged. AST parsing records 12 public boundary definitions / 25 expanded cases, all unrun. Full original sources, staged patch and raw audit output are retained. These counts do not prove runtime success, speed or identity.

Affected build group: runtime_family_host, including cfb_agglo, the historical cluster prediction operation, lifecycle and owner registrations. It consumes the existing solver, x_cluster, Xn and estimator descriptor images; those numerical provider implementations are unchanged and compatible accepted compiled outputs can be reused by the orchestrator. Required dependencies are additive Agglomerative API `2121167e8471`, completed DBSCAN API/public owner batch through `d6c5b993fa`, canonical registry API `8cb9aaa98c` plus its separately owned consumer, and DBSCAN pin-registration follow-up `12da123eea`.
