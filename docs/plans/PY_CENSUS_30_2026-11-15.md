Members fixed: 20 in product (14 ABC, 2 SVC, 4 label propagation), 9 by census attribution, 1 kept (explainer
set_params; the OrderedRMSE and FeatureFreq set_params keep the same one-frame `__init__` re-entry after the ABC
fix). Per converted site, the loop and what the old code did:

- ABC targets: every admitted setting of a constructor, fit or reset (a driver loop over fixed parameter names). The
  old code ran one or two Python ABC frames per check; the new one runs a C type test first. No allocation, no
  lookup added: the tuple is built once at connection. NumPy scalars and other registered numbers still reach the
  ABC after one or two failed C type tests.
- `svc_base`: once per decode / threshold / argmax / class-ratio step of a fit or predict (not per row). The old
  code called a Python function that did the same dict get; the new code does the dict get natively.
- `_semi_class_at`: the driver loop over the k classes, twice per predict. The old code ran ClassLabels.__getitem__
  per class; the new code reads the list slot (borrowed, no allocation).

Removed: the unread `family_msel_real` / `family_msel_integral` context entries (`model_selection.py`), and
`import numbers` from `model_selection.py` and `_iforest_impl.py`.

Unattributed entries (product Python entered outside any public member):

- `_portable_math.exp` x8000 and `isinf` x1088: FIXTURE code, not product. `tools/identity_lanes/linear.py:57`
  builds the GLM lanes' positive target with `_portable_math.exp` per element; the lowbit lane's Python oracle
  (`tools/identity_break.py:3971-4025`) calls `isinf`. Kept: they are the harness's independent oracle.
- `_FamilyFinder.find_spec` x7277 and `_CanonicalFinder.find_spec` x7264: the package's meta-path finders
  (`_families.py:157`, `_backend.py:2100`) sit first on `sys.meta_path`, so every import in the process consults
  them, the fixtures' own imports included. Import time, not a call: the census now counts them as `import_time`.
  Each returns None after one prefix test for a name outside the package. Kept (import cost, not per call).
- The other entries (`_LinearRegressorMixin.predict` x421, `_initializer.<locals>.__init__` x264 / x207,
  `forest_estimator...initialize` x105, ...) were public calls the inventory could not resolve: classes exported only
  through the live `__all__` (the expansion doors' names, which `mojolearn/__init__.py:448` adds at import) and
  constructors installed as functools.wraps wrappers. Both are fixed in the census (Part B).

## Part B: the 470 unreached

Census fixes (`41474cd8c7`, tooling only, product unchanged):

1. Live `__all__` exports join the static surface: the door classes (BayesianRidge and the rest of
   `_LAZY_NAMES`) become members, and their calls stop being unattributed.
2. A member maps every function along its wrapper chain: an installed `functools.wraps` constructor (forest
   `__init__`, 30 constructors were UNCOVERED) resolves.
3. VIA_SUBCLASS: a member never called itself whose defining function ran through another class's member (mixin
   and protocol members, the inherited `numeric_mode_used` / `vendor_used`) is reported apart from UNCOVERED.
4. Import time, private-helper entries and finalizers are attributed as above (Part A).
