Mojolearn native INT8 linalg checks, 2026-11-10

Scope and coverage per executor
  Five original (m,n,k) cases: (1,32,32), (2,96,127), (7,33,129),
  (16,64,1000), (1,1024,512). Native deterministic input generation keeps
  the old 13-bit-significand/eight-binade distribution and seed labels;
  it does not reproduce NumPy RNG's exact matrices.
  Both operands' quantizer codes and row exponents are checked against an
  independent Float64 quotient/remainder ties-to-even oracle (stronger than
  the previous A-only host/GPU product-helper comparison).
  Every INT8 GEMM cell is compared to a scalar Int64 dot product, then the
  same explicit Int64-to-float32 and power-of-two scaling seams as the
  former NumPy oracle. Every dequantized B word is checked independently.
  No product rounding, quantization, power or GEMM helper supplies expected
  values. No hashes, tolerance changes, production code or kernel changes.

Execution
  CPU calls typed decomposition.linalg_host_impl entries and checks return
  counts. Independent fixtures, generator/oracle rows and GEMM oracle cells
  run through host_parallelize. Owning lists survive borrowed pointers.
  GPU calls the existing quantize_rows_int8_device, identical_gemm_int8_into
  and dequantize_rows_int8_device. Existing pinned-buffer upload/download
  helpers are reused; one owned context submits shapes in order. Host
  preparation and oracle rows/cells run in parallel. The existing quantizer
  has one GPU thread per row; this test does not change or claim to improve
  its parallelism for one-row fixtures. No new loader or test runner.

Python removal and retained boundaries
  Removed five-case NumPy integer matmul/power/scaling/dequantization oracle
  and duplicate full host/GPU quantizer comparisons from test_linalg_lowbit.
  Keeps a 2 x 2 / 3 x 2 case for ndarray and (codes,exponents) admission,
  matching result packing, dtype/shape, raw binding counts and sentinels.
  Earlier BF16 conversion test remains unchanged. BF16 GEMM numerical cases
  and all public refusal tests remain; this file is still partially migrated.
  Inventory review corrected density-hash tests to retain-python-boundary:
  physical/logical buffers, protocols, exception semantics and lifetimes
  need the Python boundary. Their hashlib oracle is test-only.
