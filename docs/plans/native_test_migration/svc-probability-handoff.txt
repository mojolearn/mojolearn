SVC native probability contracts (2026-11-10)

Semantic selection/dependency
  test_svc_probability.py originally had seven definitions. Its first three
  tested Python _svm_reference algorithms only, without invoking native product
  kernels. They now call the actual native kernels directly in three CPU and
  three GPU fixtures. No new producer dependency: existing svm.host.svc_proba,
  svm.impl.svc_epilogue and svm.impl.svc_rows interfaces are unchanged.
  No Logistic config/state or fixed-descriptor contract files were edited.

Exact numerical scope
  Shuffle: same50 entries/seeds3 and4. Each result must contain every integer
  0..49 exactly once; repeated seed3 agrees and seed4 differs. Membership counts
  are an independent property oracle, not a copied Feistel implementation.
  Platt: original eight decisions[-2,-1.5,-1,-0.2,0.3,1,1.4,2.2] and labels
  [-1,-1,-1,1,-1,1,1,1]. Actual fitted A<0; actual sigmoid at+2 greater than0.5,
  at-2 less than0.5, with probability bounds. No copied Newton/calibration code.
  Coupling: original3x3 matrix[0,.7,.8; .3,0,.6; .2,.4,0]. Native status success,
  original sum-to-one bound1e-9 and p0>p1>p2, plus probability bounds.
  Guarded destinations/scratch and raw input-word preservation added throughout.
  No workload, tolerance, seed, matrix or algorithm simplified.

Actual calls and execution structure
  CPU host_splitmix_perm, host_platt_train, shared sp_sigmoid_predict and
  multiclass_probability. Independent fixtures run through host_parallelize;
  contract checks also split independent indices. Existing product host shuffle
  and Platt reductions retain their current algorithms; no performance claim.
  GPU device_splitmix_perm and device_platt_train use actual SVM context/kernels.
  Thin test kernels directly call the same sp_sigmoid_predict and
  multiclass_probability functions used by production epilogue_row. No test
  implementation of sigmoid or coupling. Device words use software binary64,
  as production does; host reads only completed values for independent checks.
  Two sigmoid points run on independent threads. The coupling fixture has one
  original three-class row, an inherently dependent solve. Fixture submissions
  remain ordered because SVM entries share _family_ctx. No concurrency claim.
  CPU/GPU agreement is NOT tested here; this is correctness, not identity.
