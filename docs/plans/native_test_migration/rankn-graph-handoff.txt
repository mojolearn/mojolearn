Mojolearn native rank-N attention/layout graphs, 2026-11-10

Two fixtures per executor
  Attention: Q(2,3,5,4), K(2,3,7,4), W(4,6); scores Q*K^T, softmax of
  scaled scores, attention*K*W and backward of mean(output). Independent
  Float64 scalar loops check scores, probabilities-derived outputs and the
  W gradient using the same tolerances as the old NumPy/einsum reference.
  Q/K gradients are checked for finiteness as before; no stronger analytic
  Q/K-gradient coverage is claimed. All output/native shape checks remain.
  Layout: three (3,k,5) parts with k=2,1,4; concat, split by sizes, split
  into one section, take indices [6,0,6,3] and backward of the original
  quadratic/weighted/scaled loss. Independent scalar coordinates check
  every value, every part gradient and duplicate-index scatter accumulation.
  Take uses upload_ids and a typed integer tensor handle, avoiding the
  NumPy dtype-number descriptor path in the native algorithm check.
  Native finite deterministic fixtures replace NumPy RNG arrays; shapes,
  operators, repeated indices, derivative formulas and tolerances remain.

Parallelism and boundaries
  Independent CPU graph sessions run on host_parallelize. Attention oracle
  queries (30) and W-gradient cells (24) also run independently on that pool.
  GPU fixtures submit in order to respect DeviceExec's shared context/pool;
  existing parallel kernels and host oracle tasks provide the work.
  No Python objects, callbacks, imports, new loader, hashes or timing.
  Python keeps public output/gradient shapes and dtypes, the split tuple
  contract, raw ndarray take-index admission, and a gradient route sentinel.
  Removed attention einsum/softmax and layout/scatter numerical oracles and
  double-run/digest calls. Only convolution/pooling and finite-difference
  gradient numerical checks remain in test_ops_rankn.py pending migration.
