Parallelism and lifetimes
  All independent fixtures use host_parallelize; large fixture source
  preparation and independent output/source checks also split into chunks.
  The product final writer uses its existing host grain/core policy; the check
  reports its resolved task count, not a measured busy-core count. A one-core
  runner remains a one-core result, not proof of multi-worker execution.
  Building one ordered scalar run is dependent mutation of one native plan;
  no test controller replaces parallel data conversion with Python work.
  All source Lists/pointer tables and output owners outlive the synchronous
  worker join and every final unsafe read. No Python objects or callbacks.
