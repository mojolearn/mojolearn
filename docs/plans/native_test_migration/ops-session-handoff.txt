Mojolearn native ops-session test migration, 2026-11-10

Scope
  checks/native_tests/ops_session_cases.mojo calls OpsSession[E] directly,
  with owned Mojo lists, CastIn and ShapeN. No Python imports/objects or
  binding calls. No product code, kernel, arithmetic or defaults changed.

Coverage per executor (28 fixtures)
  0-9: sub, div, minimum, tensor pow, equal with copy, not_equal,
       greater_equal, less_equal, logical_and, logical_or.
  10-15: ceil, sign, round (includes 3.5 tie), logical_not, scalar pow,
         unsqueeze including rank-3 shape.
  16-20: MAE mean/sum, Huber mean delta=1, BCE logits mean/sum.
  21-23: accuracy, ROC AUC, log loss.
  24-27: permutation membership, scalar sum, rank-4 average pool,
         step-scheduler initial and advanced learning rates.
  These replace the full NumPy numerical/oracle checks and scheduler
  assertions in test_ops_session_coverage.py. Both native executors use
  the same cases, inputs and expected-value logic. No recorded hashes.

Independent expectations
  Literal ceil/sign/round/pool outputs and label/rank counts; Float64
  arithmetic, exp/log/log1p implement the independent binary/loss/log-loss
  oracles. No product helper computes the expectations. The original
  operation/loss tolerances remain, including exact accuracy/scheduler
  assertions. Permutation asserts integer range and each index once.
  No blanket tolerance increase or expected-hash refresh.

Parallel plan
  CPU: 28 independent owned host sessions through existing host_parallelize.
  GPU: existing parallel element kernels; ordered fixture submissions.
  DeviceExec shares sequence_ctx() and its pool; concurrent sessions would
  race its ownership. This is a stated native-context limitation, not proof
  of parallel session safety. No new test runner/build system was added.

Retained Python boundary checks and reasons
  Binary/unary: public method routing sentinels, NumPy dtype and shape.
  Losses: reduction string admission/mapping, ndarray and scalar packing.
  Metrics/permutation/pooling: public arguments, result types and shapes.
  Optimizer/profile: Python result types (native learning-rate state moved).
  All dead-handle, closed-session, poison/shape/reduction refusals, and
  nonnumeric scalar refusal cases remain. They test public Python error
  translation/admission, not just internal arithmetic.
  NumPy remains solely for fixture buffers and packed-buffer checks here;
  NumPy arithmetic references and reference lambdas were removed.
