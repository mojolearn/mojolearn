## 1. GEMM (highest value, start here)

**Why.** Neural is our worst domain: the LM step is 3.78x torch eager-fp32 and
11.90x torch compile_bf16. GEMM is **145 ms of the step, 48%**; attention is
116 ms, 39%; nothing else exceeds 4.3 ms.

**The ceiling, know it before renting.** Closing GEMM to parity would take most
of the eager-fp32 gap. It CANNOT close the compile_bf16 gap: even a GEMM at
zero leaves us ~8x, because that gap is mostly bf16-against-our-fp32 plus their
fused kernels. Do not promise the headline number.

**What is actually there, checked 2026-09-13 and NOT what an earlier handoff
implied.** DEVIATIONS 2640/2641 (`kfoldv`, `kfoldv_leaf`) exist in SHIPPED code
-- `gemm/checks/gemm_identical.mojo` is the shipped implementation despite its
path (`transformer/impl/llama/modeling_llama.mojo:304` imports `identical_gemm`
from it; `bindings/_mojolearn_linalg.mojo` routes via `gemm/host_entry.mojo`).
But they have NEVER BEEN MEASURED: `grep -E '2640|2641' bench/OPPONENT_REFERENCE.md`
returns ZERO. They are selected by a RUNTIME string (`MOJOLEARN_GEMM_ARM=kfoldv`),
not a comptime gate; `gemm/` has 18 `is_defined` switches and they are almost all
`SAB_*` sabotage flags.

**First job is therefore not tuning, it is attribution.** Prove the arm reaches
the shipped path before timing it, and prove the two builds differ. An arm
selected by a runtime string in a file named `checks/` is exactly the shape that
has produced inert A/Bs twice (DEVIATION 2631 on AMD; the criteo 2634 A/B).

**Done looks like:** a measured before/after for 2640 and 2641 on both corpora,
with reach proven, plus an opponent row so the next lane does not re-measure.

## 2. Bindings: keep the DeviceBuffer alive across `fit` (unowned)

**Two independent lanes now demand it.** The board shows every GPU opponent is
timed with inputs already device-resident while ours uploads and validates
INSIDE the timed call. Magnitudes, from `ctd_spans.log`:

| cell | opponent upload EXCLUDED | our entire measured time |
|---|---:|---:|
| pca Istella-S | 1431.8 ms | 387.8 ms |
| kmeans Istella-S | 1122.4 ms | 1261.2 ms |
| kmeans taxi | 128.3 ms (cuML) | 194.4 ms |

On pca/Istella-S the work cuML excludes is ~3.7x our whole number.

**Frame it correctly or not at all.** This is a USER-FACING improvement: a user
re-fitting pays that upload too. It must NEVER be sold as a benchmark
adjustment -- changing what we time to improve a ratio is the thing the harness
exists to prevent. In-tree precedent: `_ResidentForest` in
`python/mojolearn/_forest_protocol.py` caches an owned device model across
predict calls with a `matches(...)` invalidation guard.

**Estimate 1-2 days**, dominated by the invalidation gate and a cross-vendor
identity re-check, not by the caching. A cached upload that goes stale silently
changes results.

## 4. DBSCAN: `rbc` is a low-dimension default

Measured, both ends on one board: **0.084x at d=11** (12x faster than cuML) and
**6.121x at d=220** (6x slower) -- a swing of 73x, same parameters, same agreed
clustering (ARI 0.9999999991 and 0.9999993801). The random ball cover's pruning
degrades as dimension rises until the cover stops excluding candidates; cuML's
brute force has no such cliff. Gating the default on dimension helps wide data
without touching narrow data. This is the DBSCAN lane's to act on; the sweep
deliberately moved no default.

## 7. XGBoost per-tree (now qualified, lower priority than it looked)

Still ~2x slower per tree, with mechanisms named from their source: one
segmented CUB scan repartition against our multi-launch split chain
(`row_partitioner.cuh:145-205`), partition and histogram sharing one pass
(`updater_gpu_hist.cu:405-424`), and their host never reading a histogram where
under IDENTICAL we copy back `2*argmax_blocks` values per leaf. Worth ~490 ms of
a 921 ms cell.

**But the full-size board qualified the premise**: their lossguide column is a
byte-identical rerun of depthwise (depth cap binds before `max_leaves=64=2^6`),
their taxi cells built 34% fewer leaves and are NOT-COMPARABLE, and on Istella-S
where all three arms ARE comparable we now LEAD depthwise at 0.939x. Multi-hour
kernel work with identity risk; do 1-3 first.

## Working rules that cost real time today

- **Check `git rev-parse --abbrev-ref HEAD` immediately before EVERY commit.**
  A commit landed on another lane's branch because that lane checked out mid-task,
  and the following `git push origin main` said "Everything up-to-date" while
  publishing nothing. Both commands succeeded.
- **A probe needs a control.** Four verification greps were mis-aimed or
  non-discriminating: a phrase split across two source lines returns 0 on the
  broken side too; `grep -c` counts LINES not occurrences; `git grep -l | wc -l`
  counts FILENAMES; and in zsh `for x in $VAR` does NOT word-split, so a path
  list collapses to one nonexistent filename and every check returns 0. Run the
  probe against the UNFIXED side and watch it FAIL first.
- **An A/B whose two builds hash the same is a binary compared against itself.**
  Report INERT, never "bits unchanged".
- **Never reap a box while a run is owed**, and write the pod id to
  `bench/results/runpod_leases/` so an orphan is findable outside one agent's
  context.
- **R2 first**: `tools/dataset_store.sh stage` -- per-pod setup is 2 min instead
  of 21 because the istella npz is stored DECODED.
