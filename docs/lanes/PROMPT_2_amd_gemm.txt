AMD's twelve GEMM kinds span 1.13x where NVIDIA's span 1.61x. A
shape-independent rate is what a fixed PER-PRODUCT-STEP cost looks like, and
AMD's identity seam is EIGHT issued instructions per product step against
NVIDIA's two. That is a CONTRAST, NOT AN ISOLATION: clocks and occupancy were
not excluded, so no speedup is claimed from it and neither should you claim
one until you isolate it.

THE CONTRACT CEILING IS 33.5 TFLOP/s AND IT IS PERMANENT. The identity seam
must be two issued instructions on NVIDIA (`fma.rn` then `mul.rn.ftz`),
because the three vendors' native FMAs disagree and no single-instruction
semantics exists that every column computes. Measured 2026-09-13 across all
three columns. A GEMM rewrite is therefore a 2x, not a 4x, and
"cuBLAS-competitive" is the wrong target by construction. DO NOT PROPOSE A
CONTRACT CHANGE.

=== THE WORK ===

1. THE LIVE LEVER: a `v_cmp_class_f32` spelling of AMD's flush keeps it
   POST-ROUND (the same function as `ftz`, so the contract is preserved) and
   takes the seam from 8 slots to 5. It has been compiled and counted on the
   Mac for free. DEVICE PROOF IS OWED and no arm has been built on it. Build
   it, gate it bitwise, and price it.

2. THE DEAD LEVER, DO NOT REBUILD IT: `s_setreg` takes the seam 8 -> 1 but
   hashes eb76eb53d65e0007, which matches NONE of the three semantics and
   returns 00000000 at the boundary triple. It is a defect. This was closed
   for one minute of MI300X time, which is the difference between not
   building an arm and shipping a defect.

3. WHAT THE DEAD LEVER FOUND, which is bigger than the lever: that hash is
   EXACTLY NVIDIA's `fma.rn.ftz` hash. AMD's and NVIDIA's hardware flushes
   agree BIT FOR BIT over all 262,144 triples. Only Apple differs. A
   one-instruction seam exists on two of three columns. This is a contract
   observation for Andrew and NOT a licence to change the contract.

4. AMD HAS NEVER HAD the gather-staging and hardware-flush-in-the-fold work
   that won 9% on NVIDIA as `kpack_hg`. Its row is 1, not 0, so check what is
   actually in it before assuming either way.

5. NOTE FOR SIZING, NOT FOR YOU TO FIX: a separate, smaller finding is that
   the three `proj_*` GEMM kinds run a P=1 fold that performs NO arithmetic
   (contract section 7.3 is titled "P == 1 performs NO fold addition"),
   costing 8.3 ms = 4.0% of the NVIDIA step. That is being handled
   separately. Do not duplicate it, but expect AMD to have the same fold.

BITWISE IDENTITY. IDENTICAL FP32, no tensor cores, no TF32, the RN-FMA then

changes one output bit is a DEFECT. Bits must stay equal on Apple, NVIDIA
and AMD.
