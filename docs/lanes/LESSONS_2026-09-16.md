# What 2026-09-16 taught, and what it cost

One day: 325 commits, 95 merges, about $12 of rented GPU, a Mac session crash
at the start and a 23-hour session at the end. The findings below are worth
more than the merges.

## Eight checks that could not fail, in one day

This is a pattern in how checks get written here, not eight coincidences.

1. `_ = Atomic.load[ordering = Ordering.ACQUIRE](p)` emits **zero
   instructions** on Metal AIR, PTX, GCN and host arm64 alike. The random
   forest mutex repair was written that way and was inert.
2. An A/B guarding arm independence on a whole-file `.so` sha256, which ALWAYS
   differs because the build bakes a fresh `mktemp` install name, so its VOID
   branch could never fire.
3. A hand-rolled `otool` section digest that produced nothing, hashed the empty
   string twice, and read as agreement. **`e3b0c442` is the sha256 of the empty
   string; learn the prefix.**
4. Backticks inside a double-quoted `git commit -m` executed as command
   substitution under zsh, splicing empty output into the message.
5. A negative control that dropped every path matching a pattern, removing the
   template that CARRIED the lanes, so both sides fell together and the
   inversion sat silent at zero.
6. A `stale reference` test asking `lane in LANE_REVISIONS`, **true forever**,
   silently barring every shrunk lane from the public set with no way to notice.
7. The k-means saved-model gate had no arm that could fail: the family define's
   only k-means arm lives in `host_accumulate`, which only the FIT walks, so
   predict and transform, the entire point of a saved model, were unguarded.
8. **A new shape**, and the most dangerous. Verifying that removed
   `ctx.synchronize()` calls had not caused a workspace read before write, the
   obvious lanes REACH the changed site and fire it 21 and 42 times. But every
   shape at that fixture resolves to plan 1 with `ws_floats = 1`: a one-float
   stub never written and never read, so the defect **cannot arise there at
   all**. Reached, instrumented, and still incapable of failing, because the
   DATA made the failure unexpressible. "Did the code run?" answers yes.

**The rule:** a mechanism is not trusted until it has been SEEN REFUSING
something it should refuse. Not reasoned about, not unit-tested on the passing
side. And ask whether the failure you are looking for is EXPRESSIBLE in the
configuration you are running: does the buffer this bug would corrupt exist at
this size, do the two tensors this swap would exchange differ at this step.

## Prose is not a mechanism

`LANE_STATUS_lane-identity-fixtures-light.md:306` is titled "LEFT BIG" and says
a lane stays at its size because both dimensions are load-bearing. A later lane
cut it to one step anyway, a second document carried forward only half the
reasoning, and a third recorded the opposite as fact. Nobody lied. **The number
and its reason got separated across three files and only the number travelled.**

The same shape appeared twice more: `VERIFICATION_TIERS.md` already said the
Apple column was per-release while `identity_break` still told lanes to take
their own Apple cells, and five lanes followed the tool. And a compiled
sabotage proving `byte-lm` blind to a `norm1_w`/`norm2_w` swap was sitting in a
lane status file; the audit rediscovered it from scratch and a third lane then
re-proved it.

Floors now live in `@floor(steps=(3, "why"))` next to the lane, enforced from
source, with the reason in the same expression as the number.

## Things that look like results and are not

- **A section digest is PATH DEPENDENT.** Two builds of byte-identical source
  from different directories differ in `__TEXT,__text` AND `__TEXT,__const`.
  An A/B whose arms live in separate worktrees reports DIFFER for no reason.
  Build both arms in ONE directory.
- **A whole-file `.so` digest matching is IMPOSSIBLE** for two builds through
  different `mktemp` names, so a match proves a stale copy rather than sameness.
  One agent used that as a detector, correctly.
- **`llvm-objdump --triple=amdgcn` on a host ELF disassembles nothing**, so a
  zero occurrence count there is indistinguishable from absence.
- **`nm` returns nothing for Mojo entries**, so `nm | grep -c` reads as absent.
- **A REFUSED cell is not a DIVERGENT cell.** A sabotage arm whose binary is
  missing reads REFUSED and proves nothing. Rehearse the sabotage on CPU until
  it FIRES before buying a box.
- **`n/a:transductive` is exactly sixteen characters**, so a gap scan accepting
  "a list of 16-character strings" counted placeholders as hashes. Require
  `^[0-9a-f]{16}$`.
- **A card reporting 192 GB may have 360 MiB free.** Another tenant held
  178.6 GiB. Both leg runners now log free VRAM at box acceptance; two lanes
  spent boxes rediscovering that.

## zsh, which cost more than any single bug

The Bash tool runs zsh. An unquoted `$FLAGS` does **not** word-split, so `-D`
defines silently never reach the compiler and both A/B arms become one program.
Backticks inside a double-quoted `-m` are executed. Write commit messages with
`-F` and a quoted heredoc, comparison loops in `bash`, and verify with
`git log -1 --format=%B | grep -o '<distinctive token>'`.

## My own errors, since they cost the most time

- **Pushed other sessions' commits twice** by printing `git log origin/main..HEAD`
  in the SAME command as the push, so I saw the count only after publishing
  956 lines I had not read. Inspect and push are now separate calls.
- **Told a lane the freeze commit could not move** without knowing the release
  machinery was not in it, forcing a rebuild of all three Linux sets. About
  $3.60 and an hour. The lane had it right the first time.
- **Acted on a relayed instruction over a direct one.** A peer relayed "skip
  mac" from a four-word fragment, contradicting an answer Andrew had given me
  directly. I followed it reasoning that a relay telling me to do LESS was safe.
  A direct instruction outranks a relayed one in BOTH directions.
- **Passed rental authorization to a peer session second-hand.** Permission does
  not travel peer to peer however accurately it is quoted.
- **Reported "ordered, not shaped"** for the AMD OOM from a summary rather than
  the column's own JSON, which recorded a different order entirely.

## What actually got fixed

The MI300X random forest race, closed on hardware: **436 moved / 6300 stock
against 0 / 6300 repaired**, Fisher exact p = 2.32e-135, control live at 6.921%.
An Apple regression I merged and removed inside 37 minutes. UMAP's four batch
couplings. Link 3, where a fold-index hash pinned nothing. `verify --compare`
and five ways it could agree wrongly. Public CPU verification from 39 lanes to
121, and routine lane selection from 212 lanes to tens.
