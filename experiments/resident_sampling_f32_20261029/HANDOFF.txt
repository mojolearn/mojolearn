Boundary integration is a separate generation-agent batch; core/native commits alone do not select the experiment.

Common policy uses portable FP32 exponentials, explicit FTZ arithmetic boundaries,
compensated ordered FP32 sums and 24 high SplitMix64 bits. Both host fallback and
device call the same selector. This deliberately changes seeded samples versus
the old FP64/53-bit policy; within-release vendor identity remains unqualified.
Finite IEEE ordering collapses signed zero ties to token ID. Tiny positive
temperature is normalized without unsupported FP64; rounded-zero top_p retains
at least one token. Public Float64 parameter admission remains at the boundary.

Removed repeated work: eligible reads enter native once, retain token/selector
scratch and KV for the operation, and publish final outputs/KV once. The token
loop performs no Python dispatch, per-step logits download or token upload.
This is a structural change, NOT an established speedup. One GPU worker per row
performs stable mergesort and selection and may lose badly to host sampling for
small batches/large vocabularies. No default promotion is justified.

Recovery cost: THREE times total KV storage (live plus two snapshots), allocated
once/read, and full KV D2D copies after every forward. Initial snapshot populates
one slot. Inactive-slot copies precede the existing finite-check wait; only a
successful wait and finite checks commit the slot and consumed count. Failed
forward preserves prior committed slot; sampler failure preserves the just-completed
forward and first-invalid-row prefix metadata. Completed tokens, lengths and EOS
are published only after synchronized copies; KV has a separate readiness flag.
Direct committed-snapshot export never re-enables invalid native sessions.
Best-effort cleanup/readback preserves the original error. Device/context loss or
failed readback can make diagnostics/KV unavailable; no full recovery is claimed
for those failures. No hidden fallback occurs after partial native execution.

Ownership/invalidation: descriptor lives in provider-owned heap storage, pins all
host output destinations and moves its progress/address Lists. Native sessions use
existing all-owner reservation and error invalidation. Device views, selector
scratch and both snapshots span final success synchronization and error drain.
Boundary retains existing exact-span alias, exposed-parameter and generation
checks; changed live values are admitted per operation. This adds no immutable
pointer cache. Peer boundary owns policy persistence/chunk counter and route parity.
