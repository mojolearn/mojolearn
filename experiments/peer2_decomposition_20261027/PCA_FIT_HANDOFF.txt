The dedicated operation uses classical_family_admit before model fields,

dedicated import-connected metadata context, not a training or optimizer owner.

objects with representation hooks are refused instead of invoking repr.

The whole input path is the PCA snapshot provider from the prior query chunk,
including native dense/sparse preparation, rank/type/finite refusal, one metadata
capture and original owner retention. Input copying metadata comes from that
same preparation and source type, rather than rereading X after execution.
The seven compiled fit/metadata/optional-whiten entries are identity-checked
against import-retained entry/owner/name records before either metadata reader.
Their private table is copied before use. Vendor/mode results are captured once.

Output allocation captures each pointer once. Existing pca_fit_owned and
pca_fit_randomized receive only newly boxed native addresses and dimensions.
Their bindings unpack those primitives before GILReleased and invoke
pca_fit_owned/pca_randomized_owned in decomposition/impl/pca_owner.mojo or the
corresponding core/estimators_host_impl.mojo owners. The metadata reader

scalar are committed to the original admitted model dictionary; no setting is
reread from the live model after execution.

The dedicated PCAFitScalar provider now owns scalar conversion completely;
training_scalar_native is reused only for native warning delivery. This covers
tol, n_components, n_oversamples and iterated_power, including native temporal
scalars/arrays through the pure helper7082db091c (local cherry e4fa50751b).
Temporal dtype/layout and eight raw bytes are captured before input work;
calendar category/range decisions are native. Neither NumPy number slots nor
Python date/calendar helpers execute. Exact native scalar admission precedes
legacy sequential admission so long double/complex/temporal scalars can reach
the dedicated decoder. Primitive strings/bytes are boxed as native builtin
text before the fixed CPython parser. Unsupported protocols are refused.

An array.array setting keeps its exact native wrapper and typecode around a
private bytes copy so native integer/float parser error representation/type is
preserved. The previous conversion to bare bytes was repaired. Structured void
number conversion uses a native empty tuple to retain integer-specific versus
float-specific refusal; no field conversion is needed to refuse a record.

Whiten now uses dedicated native truth handling for numeric/complex/temporal,
text/object arrays, structured/raw void and builtin containers/buffers. It
freezes the result before input preparation. Empty-array truth retains the
NumPy2.2 transition from warning/False to ValueError. Structured fields are
walked natively with ordinary owned scalar snapshots; Python truth hooks are
refused before execution. Query truth reuse is a separate followup target.

Deferred native scalar item errors now own the exact CPython (type,value,
traceback) triple using the same supported FetchTriple/Restore ownership
pattern as ByteCheckpointIOError. A native item-boxing allocation or dtype
boxing failure need not preempt the original input-validation stage. The
record restores the captured exception only when its setting is consumed;
unused records release owned references normally. No error category is guessed
from a filtered log or reconstructed Python callback.
