Repair:
_items no longer calls __iter__/__next__ attributes or treats every exception
as exhaustion. The existing public sequential_admit_value gate already rejects
arbitrary user iterators; this is NOT a reproduced public custom-iterator bug.
Errors from remaining admitted native iterators previously could be swallowed.
PyIter_Next now stops only on null without an error (including StopIteration);
other native errors reach small_mlp_c with their original exception/traceback.
Original iterator-construction TypeError refusal wording/order is retained.

Removed work and setup/reuse boundary:
- Exact list/tuple: read count once, reserve once, native borrowed get-item plus
  NewRef. No iterator object, per-element attribute lookup/call or index boxing.
  Element references and limits retain their original meaning.
- Exact Array: one admitted metadata/storage snapshot; 1D uses existing native
  scalar conversion, rank2+ uses existing native C-order preparation and direct
  _row calls. No Array.__iter__, map, partial or per-row compiled-entry dispatch.
  Retains all 9 supported dtypes, half conversion, F-order conversion, limits,
  readonly/shape/zero-copy row storage semantics. Row owner chains include the
  private passive snapshot, which pins the original Array and actual buffers.
  This newly refuses inconsistent/tampered Array metadata through the existing
  native snapshot guard; supported consistent arrays remain admitted.
- Exact Tensor/Parameter: native admission then TensorBase.unbind(0), replacing
  Python Tensor.__iter__ without converting tensors to NumPy or host scalars.
  Keeps dtype/device/row views and eager unbind-before-limit behavior. Admitted
  descriptor lookup occurs once; row tuple traversal uses the direct helper.
- Remaining admitted native iterators: resolve GetIter/Next once per operation;
  preserve the distinct exhaustion/error result rather than blanket except.

Lifetimes / invalidation / errors:
All new prepared objects are operation-local. Full mutable Array admission is
performed each time; the snapshot owns real exports. After a possible native
F-order reorder/GIL release, Array storage descriptors are readmitted before row
construction. Only a selected exact native reorder callable is retained; local
context dictionaries hold exact native dtype metadata, not caller callbacks.
Torch dispatch modes are admitted before native unbind; Python iteration is not
used. List/tuple owners survive all borrowed item NewRef acquisitions. Native
iterator/error references remain owned during unwind. Source review caught that
_locked calls lock.release during unwind: existing ByteCheckpointIOError ownership
now fetches/restores the pending error around that cleanup, preserving the first
error even if unlock fails. No global pending-error cache was introduced.
