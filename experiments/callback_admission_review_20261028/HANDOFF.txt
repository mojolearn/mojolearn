Implementation: Samba registry setup/reuse
------------------------------------------
Classical lane found per-row builtins.list imports in _samba_registry. The
shared configuration registry also rebuilt the same per-kind shape/name
schema, scalar configuration reads, and shape tuples for every model layer.

samba_registry now lazily builds at most one Mamba and one attention schema
inside the operation, captures config.layers once, and constructs the layer
name prefix once per layer. Each output still has a distinct named registry
record in the original order. Shared dimensions are immutable builtin tuples.
Only a used kind is constructed; first-use errors remain ordered by layers.

_samba_registry retains each row/shape while validating it, resolves the list
constructor once, and still performs every dimension/overflow/offset check in
row order. Each published mutable shape list is newly constructed as before.
This removes repeated metadata work; it does not change numerical arithmetic.

Ownership/invalidation: admission fixes native config values and guards class
metadata before these GIL-held helpers. No GIL release/user callback is added.
Local PythonObject owners retain both schemas, layer sequence, row, shape and
constructor through their uses. There is no raw pointer or cross-call cache.
Each later public operation re-admits configuration and rebuilds schemas, so
changed configurations/layers are reflected. Mutable output lists do not alias
between records. The reuse does not extend to model buffers.

Qualification: focused Mac arm64 CPU identical compile exports samba_registry,
samba_block_shapes and _samba_registry. It compiles both schema branches and
flat registry validation/conversion; no model execution or public-operation
runtime was performed. Full outputs, binary, provenance/source bytes and source
push guard results are retained beside compile.json. No speed, runtime or
cross-vendor identity claim is made. No rented machines.

Remaining work: repeated registry construction across public calls and other
PythonObject/native boundary metadata remain. A retained cache would need an
explicit immutable admission/version owner. This batch deliberately keeps
operation-local invalidation. Full callback inventory closure remains pending.
